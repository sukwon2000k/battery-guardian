# 배터리 지킴이 — 기기 테스트용 소스

잠든 사이 설정한 시간대에 배터리가 기준 이하가 되면 지원 미디어에 일시정지를 요청하고, 홈 이동과 화면 잠금을 실행하는 Kotlin 앱입니다.

**상태: 소스 작성·정적 검사 완료. APK 빌드와 실제 기기 검증은 미완료입니다.** 기존 저장소의 Android SDK·Gradle 버전은 유지했습니다. 이 패키지는 이전 대화의 임시 작업 폴더를 복구한 것이 아니라, GitHub 기본 프로젝트에서 다시 구현한 버전입니다.

## 포함한 기능

- 보호 OFF: 아이보리 화면 + 앉은 양 / ON: 남색 화면 + 잠든 양. 설정 위치는 고정됩니다.
- 시간 프리셋과 직접 시간 선택. 기본 00:00~07:00, 기본 잔량 20%.
- 잔량 선택 10·15·20·25%. 설정은 Preferences DataStore에 자동 저장.
- 배터리 이벤트·분 변경·설정 변경·서비스 연결·보호 시간 경계에서 조건 평가.
- 충전 연결 중 제외. 시작 포함·종료 제외. 자정을 넘는 구간 처리.
- 보호 요청을 날짜별로 한 번만 기록. OFF/ON으로 바꾸거나 시간을 바꿔도 그날의 요청 기록은 초기화하지 않습니다.
- 실제 서비스 연결과 권한을 확인하고, 준비되지 않았으면 보호 중으로 표시하지 않습니다.
- 권한 사용 설명과 사용자 동의 후 운영체제 설정 열기.
- 가상 조건 테스트 / 5초 취소 가능한 실제 보호 테스트 / 마지막 요청 결과 표시.
- 서버·광고·분석 SDK·인터넷 권한 없음. 원본 양 이미지 2장을 포함합니다.

## Android Studio에 적용

기존 폴더는 그대로 두고 별도 폴더에서 먼저 확인하는 방법을 권합니다.

1. ZIP을 전부 압축 해제합니다. `battery-guardian` 폴더 안에 `settings.gradle.kts`, `gradlew.bat`, `app`이 있어야 합니다.
2. Android Studio 시작 화면에서 **Open**으로 그 `battery-guardian` 폴더를 선택합니다. `app`만 열지 마세요.
3. 처음 열 때 프로젝트 신뢰·Gradle Sync 안내를 확인하고 필요한 SDK를 설치합니다.
4. 기존 프로젝트는 **compile/target SDK 37, Gradle 9.6.0, AGP 9.5.0**을 사용하며 daemon toolchain은 **JDK 25**입니다. 이 패키지는 해당 버전을 임의로 낮추지 않았습니다. Android Studio의 Gradle JDK와 설치 SDK가 맞는지 확인해주세요.
5. Gradle Sync가 성공하면 에뮬레이터 또는 S22+를 선택하고 **Run ▶**으로 실행합니다.

에뮬레이터에서는 UI·설정·가상 조건을 먼저 확인하고, 미디어 제어·야간 유지·재부팅은 S22+에서 확인하세요.

터미널로 빌드하려면 프로젝트 최상위에서 실행합니다.

```powershell
# Kotlin 조건 판단 테스트와 디버그 APK 빌드
.\gradlew.bat testDebugUnitTest assembleDebug
```

성공했을 때 APK 위치: `app/build/outputs/apk/debug/app-debug.apk`.

`local.properties`는 컴퓨터별 Android SDK 경로이므로 포함하지 않았습니다. Android Studio가 생성합니다. 프로젝트 버전을 찾을 수 없다는 오류가 나면 오류 원문을 확인해야 하며, 임의의 최신 버전으로 한꺼번에 바꾸지 마세요.

## S22+ 연결과 권한

1. 휴대폰에서 개발자 옵션과 USB 디버깅을 켭니다.
2. USB로 연결해 휴대폰의 디버깅 허용 안내를 확인합니다.
3. Android Studio의 실행 기기 목록에서 S22+를 선택하고 Run을 누릅니다.
4. 앱의 **권한 안내 → 접근성 사용 안내 → 동의하고 설정 열기**에서 배터리 지킴이 접근성을 켭니다.
5. 앱으로 돌아와 **알림 접근 사용 안내**를 읽고 알림 접근도 허용합니다. 일반적인 알림 표시 허용과 다른 설정입니다.
6. 앱으로 돌아오면 두 연결 상태를 확인합니다. 연결 대기 중이면 잠시 기다렸다 다시 확인합니다.

접근성은 홈 이동·잠금과 알람 화면 회피에 사용합니다. 화면 내용과 입력값을 읽지 않습니다. 창 이벤트의 패키지 이름은 메모리에서만 사용합니다. 알림 접근은 지원 미디어 세션을 제어하는 용도이며 알림 본문은 조회·저장·전송하지 않습니다.

APK 직접 설치 시 운영체제가 제한된 설정을 표시할 수 있습니다. Android Studio의 Run 설치로 먼저 시험하세요. 권한 설정 경로는 Android·One UI 버전에 따라 달라질 수 있습니다.

## 첫 테스트

1. **테스트 → 가상 조건 테스트**를 엽니다. 이 창은 실제로 잠그지 않습니다.
2. 시작 시각, 잔량 20%, 충전 OFF에서 실행 대상으로 판정하는지 확인합니다.
3. 종료 시각·충전 ON·가상 보호 OFF·같은 밤 실행 이력 ON을 각각 바꾸어 실행을 막는지 확인합니다.
4. 두 권한 연결 후 **실제 보호 테스트로 이동 → 5초 후 실행**을 누릅니다. 시간·잔량·충전·자동 보호 ON/OFF는 이 테스트에서 무시합니다. 통화·알람 회피와 권한 확인은 유지합니다.
5. 취소 버튼 또는 화면 이탈로 카운트다운이 취소되는지 먼저 확인합니다.
6. 다시 실행해 홈 이동·화면 잠금과 앱 하단의 마지막 결과를 확인합니다. 자동 보호의 그날 실행 이력은 수동 테스트로 소모되지 않습니다.

실제 미디어 중단은 유튜브를 재생한 뒤 앱으로 돌아와 테스트하세요. 일반 유튜브는 앱 이동 자체로 재생이 멈출 수 있으므로 이것만으로 미디어 제어 성공을 판단하면 안 됩니다. 백그라운드 재생 가능한 유튜브 또는 지원 음악 앱에서도 별도로 확인하세요.

자동 조건 확인은 보호 시간을 현재 시각이 포함되도록 정하고, 현재 잔량이 선택 기준 이하인 상황에서 충전기를 분리한 뒤 자동 보호를 켭니다. 그날 자동 보호 요청 이력이 있으면 반복 실행하지 않습니다. 추가 동작은 수동 테스트로 확인하세요.

## 실제 동작과 한계

- 미디어 제어 대상: 유튜브, 유튜브 뮤직, Spotify, 삼성 뮤직, VLC. 해당 앱이 활성 미디어 세션과 일시정지 동작을 제공해야 합니다. 모든 미디어 앱을 지원한다고 표시하지 않습니다.
- 기록의 '일시정지 요청'은 앱이 재생을 멈췄다는 확인이 아닙니다. 홈/잠금의 성공은 접근성 API의 반환값입니다.
- 다른 앱 프로세스의 강제 종료는 하지 않습니다. 게임의 백그라운드 동작이 남을 수 있습니다.
- 통화·통신 오디오 또는 기본 시계 앱 화면이 감지되면 보호를 미룹니다. 모든 타사 전화·알람 앱을 판별하지는 못합니다. 시스템 알람 설정·음량·방해금지는 변경하지 않습니다.
- 처음 보호 동작을 요청하기 전에 이력을 저장합니다. 도중에 실패하거나 서비스가 종료돼도 그날 자동 재시도하지 않습니다. 반복 잠금 방지가 우선입니다. 실패 결과를 확인하고 수동 테스트를 사용하세요.
- 감시는 시스템에 연결된 접근성 서비스에서 수행합니다. 앱 화면을 닫아도 연결이 유지되면 감시할 수 있지만 제조사의 절전·프로세스 종료에 영향을 받습니다. 강제 중지 후 지속 실행을 보장하지 않습니다.
- 재부팅 후 접근성 서비스가 실제로 다시 연결돼야 합니다. 예약 수신기만으로 접근성 권한을 켜거나 화면 잠금을 수행할 수는 없습니다.
- 시작·종료 경계는 비정확 알람으로 예약해 추가적인 정확한 알람 권한을 요구하지 않습니다. Doze나 절전 정책에 따라 시작 시각의 평가가 늦어질 수 있습니다.
- 절전 모드 자동 켜기와 Google Play 출시 절차는 포함하지 않습니다.

## 코드 위치

| 파일 | 역할 |
|---|---|
| `MainActivity.kt` | 단일 화면·권한 고지·테스트 도구 |
| `SettingsRepository.kt` | 로컬 설정·마지막 결과 저장 |
| `ProtectionEvaluator.kt` | 시간·잔량·충전·반복 실행 판단 |
| `ProtectionService.kt` | 이벤트 감시·미디어 제어·홈 이동·잠금 |
| `GuardianRuntime.kt` | 서비스 연결 상태·시간 경계 예약·재부팅 수신 |
| `res/xml/protection_accessibility.xml` | 접근성 서비스 설정 |
| `ProtectionEvaluatorTest.kt` | 경계와 예외의 Kotlin 단위 테스트 |

## 검증 현황

`TESTING.md`에 수행한 검사와 아직 수행하지 못한 기기 검증을 구분했습니다. 이 환경에서는 Gradle 다운로드가 네트워크 제한으로 실패해 APK를 만들지 못했습니다. APK와 실기 테스트를 완료했다고 주장하지 않습니다.

`.github/workflows/android.yml`은 GitHub Actions용 빌드 설정입니다. 저장소에 올려 실행 결과를 확인해야 하며, 포함되었다는 사실만으로 빌드 성공은 아닙니다. 워크플로가 성공하면 `battery-guardian-debug` artifact에서 APK를 받을 수 있습니다.
